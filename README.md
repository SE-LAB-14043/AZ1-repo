# اقتصادیار (AZ1-repo)

این مخزن شامل یک رابط وب ساده برای محاسبات مالی (محاسبه سود صندوق درآمد ثابت و محاسبه اقساط وام) است که به عنوان تمرین آزمایشگاه مهندسی نرم‌افزار (SE-LAB-14043) ساخته شده است.

این README یک توضیح کامل از پروژه، ساختار فایل‌ها، راهنمای اجرا، و یک بخش مفصّل دربارهٔ نحوهٔ مدیریت شاخه‌ها و کامیت‌ها و همچنین دستوراتی برای تولید گزارش کامل از تاریخچهٔ گیت را در بر دارد.

---

## ساختار پروژه (خلاصه)

- `src/` : کدهای HTML/CSS/JS صفحات
  - `pages/` : صفحات جداگانه (`index.html`, `profit.html`, `loan.html`, `about.html`)
  - `styles/` : فایل‌های CSS (global, responsive, footer, profit, loan, about)
  - `components/navbar/` : ناوبار کامپوننت
  - `js/` : منطق جاوااسکریپت مربوط به صفحات (`loan.js`, `profit.js`)

## استقرار روی Github Actions
پس از Merge شدن تغییرات در main، فرآیند استقرار پروژه به صورت خودکار توسط GitHub Actions انجام می‌شود.

به این معنی که توسعه‌دهنده پس از اینکه تغییرات خود را در Branch مربوطه پیاده‌سازی کرد، نیازی ندارد به صورت دستی فایل‌ها را روی سرور قرار دهد.
با قرار گرفتن تغییرات در main، GitHub Actions به صورت خودکار Workflow مربوط به Deployment را اجرا کرده و نسخه جدید نرم‌افزار روی GitHub Pages مستقر می‌شود.

شما می‌توانید این دستیار را از طریق آدرس زیر مشاهده فرمایید.

https://se-lab-14043.github.io/AZ1-repo/

## اجرای محلی

فایل‌ها HTML/CSS/JS خالص هستند — برای دیدن پروژه کافیست فایل‌های داخل `src/` را در مرورگر باز کنید یا یک وب‌سرور ساده اجرا کنید:

```bash
# با Python (ساده‌ترین): از پوشه‌ی src اجرا کنید
cd src
py -m http.server 8000
# سپس در مرورگر به http://localhost:8000 بروید
```

## شاخه‌ها

برای مدیریت بهتر فرآیند توسعه، پروژه به صورت Branch-Based توسعه داده شده است؛ به این صورت که هر قابلیت جدید در یک شاخه مستقل توسعه داده شده و برای اصلاح مشکلات نیز شاخه‌های جداگانه‌ای در نظر گرفته شده است. پس از تکمیل هر قابلیت، تغییرات ابتدا وارد شاخه `stage` شده و در آنجا مورد بررسی و آزمایش قرار گرفته‌اند. پس از اطمینان از صحت عملکرد، تغییرات از طریق Pull Request به شاخه اصلی پروژه یعنی `main` منتقل شده‌اند.

همچنین شاخه `main` به وسیله قابلیت **Branch Protection** در GitHub محافظت شده است و امکان Push مستقیم به آن وجود ندارد. بنابراین ورود تغییرات به شاخه اصلی تنها از طریق Pull Request انجام می‌شود.

### main

شاخه `main` شاخه اصلی و پایدار پروژه است. نسخه‌ای که در این Branch قرار دارد، نسخه‌ای است که پس از بررسی و تأیید تغییرات آماده انتشار محسوب می‌شود.


### stage


شاخه `stage` به عنوان محیط میانی برای بررسی و آزمایش تغییرات استفاده شده است.

هدف از ایجاد این Branch این بوده است که تغییرات قبل از ورود به `main` یک مرحله کنترل و تست را پشت سر بگذارند.

و تست را پشت سر بگذارند.

روند کلی به این صورت بوده است:

```text
Feature / Fix Branch
        ↓
      stage
        ↓
      Test
        ↓
   Pull Request
        ↓
      main
```

به عنوان مثال، زمانی که توسعه یک قابلیت در Branch مربوط به آن به پایان می‌رسید، تغییرات آن ابتدا وارد stage می‌شدند. در این مرحله عملکرد قابلیت جدید در کنار سایر قسمت‌های پروژه بررسی می‌شد تا مشکلات احتمالی مانند ناسازگاری بین قابلیت‌ها، خطاهای ظاهری  مشخص شوند.

### features

برای هر قابلیت جدید پروژه یک Branch مستقل ایجاد شده است تا توسعه هم بتواند به صورت موازی پیش برود و هم مستقل از شاخه‌های دیگر باشد.

برای مثال Branch‌های زیر در پروژه ایجاد شده‌اند:


```text
feature/home-page
feature/nav-bar
feature/footer
feature/about-page
feature/loan-page
feature/profit-page
```

### fix

برای برطرف کردن Bug‌ها یا مشکلات موجود در پروژه نیز Branch‌های جداگانه ایجاد شده‌اند.
برای مثال اگر بعد از تست در stage مشخص شود که یک قابلیت دارای مشکل است، به جای تغییر مستقیم stage یا main، یک Branch مخصوص رفع مشکل ایجاد می‌شود. مثل


```text
fix/repo-address-fix
```

### docs

برای اضافه کردن اسناد لازم در پروژه. مثلا اینجا اضافه کردن گزارش پروژه و پاسخ به سوالات

```text
docs/complete-readme
```

## استفاده از Commitهای معنادار

در فرآیند توسعه پروژه تلاش شده است هر Commit نشان‌دهنده یک تغییر مشخص و قابل تشخیص باشد و از اسامی کلی و پیام‌های کلی حلوگیری شده است.

به عنوان مثال Commitهایی با عناوینی مانند:
```text
added home page
added about page
added profit feature
added first state of calculating loan
added second state of calculating loan
fixed github workflow
```
